# P4 — Data Layer, Auth/Licensing/Audit, and Schemas (O3, O5, O7)

## (a) Scope & Non-Goals

**Scope.** The Gateway's durable-state foundation: (1) Postgres schema v1 (multi-tenant from day one per arch §5.9) covering tenants/users/devices/seats, sessions and session state, the audit/invocation log, LLM metering, result_refs, Tool-Registry storage tables, and bridge release/channel tables; (2) object-storage layout; (3) the O7 unified event schema (`revagent.event.v2`) — the single envelope that carries audit, metering, and latency data and that the migrated Dashboard and Usage Intelligence consume (arch §5.10 design rule: no separate collection pipeline); (4) the O11 metric-parity mapping — which currently tracked metrics map to which event fields, and which workstation-era metrics die; (5) Phase-1 auth: OIDC for tenant #1, device-token enrollment/rotation/revocation for bridges, RBAC `user`/`admin`; (6) the O5 licensing/entitlement model and its enforcement points.

**Non-goals.** The bridge↔gateway wire protocol itself (O1 package — this package only defines what gets persisted about it); bridge self-update mechanics (O9 package — this package owns only the `bridge_releases`/channel data model); APS OAuth apps and token lifecycle (O4 package); the Dashboard/Usage-Intelligence UI rewrites (admin-plane package — this package guarantees their inputs exist); code-execution sandbox (O2); historical-data migration — **none**, closed in O11: the new store starts empty; NAS `reports\` stays as a read-only archive until NAS retirement.

## (b) Plan-Level Design Decisions (proposals; do not conflict with D1–D12)

- **P-DATA-1 — Two typed hot tables + one generic event table.** `tool_invocations` and `llm_calls` get dedicated, partitioned, strongly-typed tables (they are the query-heavy audit and metering surfaces); all other event types land in a generic append-only `events` table with a JSONB payload. *Rationale: the dashboard/UI queries hammer exactly two shapes; everything else is low-volume lifecycle history.*
- **P-DATA-2 — Catalog vs tenant-scope split under RLS.** Every tenant-data table carries `tenant_id NOT NULL` with Postgres Row-Level Security enabled from day one (session GUC `app.tenant_id`); vendor-global catalog tables (`modules`, `tools`, `tool_versions`, `instruction_docs`, `bridge_releases`, `release_channels`, `promotion_registry`) are vendor-scoped and RLS-exempt, with per-tenant state held in join tables (`tenant_modules`, `seat_assignments`). *Rationale: preserves §5.9's isolation intent while keeping one product catalog for all tenants (D2: one codebase, deployment is a sales option).*
- **P-DATA-3 — Monthly declarative partitioning on `tool_invocations`, `llm_calls`, `events`** keyed on `started_at`/`created_at`, with a maintenance job that pre-creates partitions and archives expired ones to object storage. *Rationale: retention becomes partition-drop, not DELETE storms, on the Phase-1 spare-PC host.*
- **P-DATA-4 — UUIDv7 primary keys for all event-like rows.** *Rationale: time-ordered inserts avoid index fragmentation and give a free global sort key.*
- **P-DATA-5 — MinIO as the Phase-1 object store** (one more Compose service on a filesystem volume), accessed only through an S3-compatible client interface. *Rationale: §7 requires an "object-storage volume"; S3 API from day one makes the SaaS move a config change (12-factor), and MinIO runs air-gapped.*
- **P-EVT-1 — One envelope, typed payloads.** All events share `revagent.event.v2` envelope fields (`event_id`, `event_type`, `occurred_at`, `recorded_at`, `tenant_id`, `source{component,version,instance}`, `actor{type,user_id?,device_id?}`, `session_id?`, `turn_id?`, `seq`); payloads are per-type and validated with zod schemas shared as a TS package. *Rationale: audit + metering + latency in one schema is the §5.10 design rule; typed payloads keep parity checkable.*
- **P-EVT-2 — Heartbeats are state, not history.** Bridge heartbeats update `devices.last_seen_at` and the in-memory connection registry only; they are never persisted as events. Only transitions (`bridge.connected`/`bridge.disconnected`) are events. *Rationale: today's 5-second heartbeat file writes (telemetry.ts:1709-1726, default `REVAGENT_LIVE_STATUS_HEARTBEAT_MS`=5000) would generate ~17k rows/machine/day of pure noise; the gateway holds the live WSS, so liveness is authoritative without polling files.*
- **P-EVT-3 — Port the existing summarizers, not the raw payloads.** The audit row's `params_summary` and `code` blocks reuse the proven bounding semantics of `summarizeTelemetryParams` (keys, counts, safe enums, bounded text with hash/length, `installer/runtime-mcp-server/src/utils/telemetry.ts:378-422`) and `summarizeCode` (hash, length, lineCount, writePatterns, hasManualTransaction, bounded preview, telemetry.ts:325-342), ported to a shared gateway TS lib. Additionally a full-fidelity `params_digest` = SHA-256 over canonical JSON of the raw params satisfies arch §5.1.4's "params digest". *Rationale: these bounds are field-proven (no multi-MB events) and every sendCode/Usage-Intelligence parity metric is computed from exactly these fields.*
- **P-EVT-4 — Status-poll exclusion survives.** The successor of `get_revit_mcp_status` (`core.session.status`) is excluded from audit events by registry flag (`audit_exempt`), mirroring today's `shouldRecordMcpTool` gate (telemetry.ts:1813-1818). *Rationale: agents poll it constantly; auditing it bloats the table with zero liability value.*
- **P-EVT-5 — `production.context` becomes an embedded `context` block on `tool.invocation`,** not a second event. Fields carried over 1:1 from `revagent.production.context.v1` (project id/title/path, active/before/after view, level/room/space, categories, discipline hint, bounded element samples, outputs, search-policy block — telemetry.ts:1102-1179). *Rationale: one pipeline (§5.10); the context is derived from the same invocation's params/response, so a separate event only creates join pain.*
- **P-AUTH-1 — Keycloak (container in the Compose stack) is the OIDC provider for tenant #1;** the Gateway implements only generic OIDC (discovery + auth-code + PKCE) and OAuth2 resource-server validation for the north MCP surface, so any customer IdP (Entra ID, Google, Okta) is a config swap later via Keycloak brokering or direct pointing. Evaluated simply: Entra/Google were rejected for Phase 1 because the office has no central IdP today (identity is literally `process.env.USERNAME`, telemetry.ts:1745) and the on-prem/air-gapped variant (D8/D2) cannot depend on an external identity cloud; Auth0 adds cost and the same external dependency. *Rationale: free, air-gap capable, standard OIDC + dynamic client registration (needed for MCP OAuth), and it deploys as one more `compose` service per §7.*
- **P-AUTH-2 — Device tokens are opaque 256-bit secrets, stored hashed.** Admin mints a single-use, TTL-bound enrollment code (dashboard/CLI); the bridge exchanges code + machine fingerprint for the token exactly once; DB stores only `sha256(token)`. Rotation: gateway directs rotation at connect when token age > 30 days, old token stays valid for a 24 h grace window (crash-safe mid-rotation); revocation: `devices.status='revoked'` closes the live connection and rejects handshakes. Every transition emits an `auth.event`/`bridge.*` event. *Rationale: matches arch §5.4 enrollment; hash-at-rest means a DB leak leaks no credentials.*
- **P-AUTH-3 — RBAC as a role enum with the full future value set from day one:** `user | tenant_admin | vendor_admin` (Phase 1 uses `user` and `tenant_admin`; `vendor_admin` reserved per §5.10). Admin roles gate the admin-plane APIs, enrollment-code minting, and seat management. *Rationale: enum widening later is a migration; reserving values now is free.*
- **P-LIC-1 — Named-user seats (recommended), per module.** A license row grants N seats for a module (`core`, `mech`, `arch`, `struct`, `elec`); seats are assigned to named users; concurrent-bridge counting is rejected. *Rationale: (1) reviewers (persona b) have no bridge at all, so bridge-based seat counting cannot license half the user base; (2) the audit/liability chain (§6, "who changed what") requires stable named actors anyway; (3) customers on Revit/ACC already buy named-user subscriptions (Autodesk model since 2020), so the mental model matches; (4) enforcement is race-free at assignment time instead of contended at connection time. A reassignment-cooldown policy field exists but is not enforced in Phase 1.*
- **P-LIC-2 — Three enforcement points.** (1) **Connection/session admission:** bridge handshake verifies device ∈ tenant, tenant license valid; user session start verifies a `core` seat. (2) **Capability-index generation:** the Tool Registry emits index lines only for modules where the acting user holds a seat — unlicensed tools are invisible to the LLM (no denial churn mid-plan; aligns with D5 per-tenant index generation). (3) **Dispatch defense-in-depth:** the tool runtime re-checks entitlement per invocation and emits `entitlement_denied` on failure — protects against stale cached indexes and direct north-MCP clients (D9). *Rationale: invisible-when-unlicensed is the UX; dispatch check is the security boundary.*
- **P-AUD-1 — Audit content per §5.1.4, one row per invocation, upserted by idempotency key.** `tool_invocations` is keyed uniquely on `(tenant_id, idempotency_key)`; a redelivered invocation (bridge journal replay, arch §5.4) updates the existing row rather than duplicating it. *Rationale: audit must record what happened once, exactly once, even on flaky remote links.*

## (c) Postgres Schema Sketch v1

Tenant-scoped tables (all: `tenant_id UUID NOT NULL REFERENCES tenants`, RLS enabled):

- **tenants** (id, name, slug, status, settings JSONB, data_residency, created_at). Retention: forever.
- **users** (id, tenant_id, oidc_issuer, oidc_subject, email, display_name, role enum(user,tenant_admin,vendor_admin), status, created_at, last_login_at; UNIQUE(tenant_id, oidc_issuer, oidc_subject)). Retention: forever (soft-delete/anonymize on offboarding).
- **devices** (id, tenant_id, machine_name, os_info JSONB, enrolled_by→users, enrolled_at, device_token_hash, token_issued_at, token_prev_hash, token_prev_expires_at, status enum(active,revoked), bridge_version, addin_version, revit_versions JSONB, last_seen_at, last_connected_at, revoked_by, revoked_at). Successor of the NAS `reports\machines\<MACHINE>` tree. Index: (tenant_id, machine_name) unique. Retention: forever.
- **enrollment_codes** (id, tenant_id, code_hash, created_by, expires_at, used_by_device, used_at; single-use). Retention: 90 days.
- **licenses** (id, tenant_id, module_id→modules, seats_total, valid_from, valid_until, terms JSONB). Retention: forever.
- **seat_assignments** (id, tenant_id, license_id, user_id, assigned_at, assigned_by, released_at NULL; partial-unique on (license_id, user_id) WHERE released_at IS NULL; seat count enforced by trigger/txn check against seats_total). Retention: forever (history is the licensing audit).
- **sessions** (id, tenant_id, user_id, device_id NULL, client_type enum(web,mcp,bridge), state, started_at, last_activity_at, ended_at, ended_reason, document_context JSONB, discipline_hint). Index (tenant_id, started_at DESC). Retention: 12 months.
- **session_state** (session_id PK, tenant_id, projection JSONB, plan JSONB, updated_at) — the §5.2-stage-1 server-side projection source; separated from `sessions` because it is rewritten every turn. Retention: pruned at session end + 30 days.
- **session_events** (id, tenant_id, session_id, seq, kind enum(message,plan,summary,confirmation,system), payload JSONB, created_at) — chat/plan timeline. Partitioned monthly. Retention: 90 days.
- **tool_invocations** (id UUIDv7, tenant_id, session_id, turn_id, invocation_seq, actor_user_id, device_id NULL, tool_version_id→tool_versions, tool_name, namespace enum(core,mech,arch,struct,elec), policy_class enum(auto,confirm,gated), executor enum(bridge,aps,internal), document_id, model_guid NULL, params_digest CHAR(64), params_summary JSONB, code JSONB NULL, context JSONB NULL, outcome enum(completed,guarded,failed,denied,cancelled,timeout), error_class enum(retryable,terminal,parameter_fault,environment_fault) NULL, error_message TEXT bounded, duration_ms, bridge_ms NULL, queue_ms NULL, request_bytes, response_bytes, idempotency_key, batch_id NULL, confirmation_id NULL, result_ref NULL, started_at, finished_at). Partitioned monthly on started_at. Indexes: (tenant_id, started_at DESC); (tenant_id, tool_name, started_at); (tenant_id, session_id, invocation_seq); UNIQUE (tenant_id, idempotency_key). **This table is the audit log (§5.1.4 fields: actor=actor_user_id/device_id, tenant, session, document/model id, tool, params digest, policy class, outcome, timestamps).** Retention: 12 months hot; archived to object storage (zstd NDJSON) then partition-dropped; per-tenant override later.
- **llm_calls** (id, tenant_id, session_id, turn_id, provider, model, role enum(router,planner,main,subagent,summarizer), engine_mode enum(tool_calling,code_exec), input_tokens, output_tokens, cache_read_input_tokens, cache_creation_input_tokens, latency_ms, stop_reason, outcome, cost_microusd NULL, created_at). Partitioned monthly. Index (tenant_id, model, created_at). Retention: 12 months hot; **usage_rollups_daily** (tenant_id, date, model, tool_name, user_id, counters…) kept forever.
- **events** (id UUIDv7, tenant_id, event_type, occurred_at, recorded_at, source JSONB, actor JSONB, session_id NULL, payload JSONB). Everything that is not an invocation or LLM call: `session.started/.ended`, `turn.completed`, `tool.confirmation`, `bridge.connected/.disconnected/.enrolled/.revoked`, `bridge.update`, `auth.event`, `registry.published`. Partitioned monthly. Retention: 12 months (auth/bridge lifecycle kinds: 24 months).
- **result_refs** (id, tenant_id, session_id, invocation_id, ref_label e.g. "R17" unique per session, content_type, byte_size, row_count NULL, storage_key, summary JSONB, created_at, expires_at). Retention: 7 days (row + object deleted by expiry job; §5.2 stage 5).

Vendor-catalog tables (no tenant_id; P-DATA-2):

- **modules** (id, name enum(core,mech,arch,struct,elec), display_name, status). **tenant_modules** (tenant_id, module_id, enabled, valid_until) — the entitlement join.
- **tools** (id, module_id, name — the D6-namespaced registry name, current_version_id). **tool_versions** (id, tool_id, version, json_schema JSONB, capability_line TEXT — the D5 one-liner, policy_class, executor, audit_exempt BOOL, min_bridge_version, status enum(draft,published,deprecated), created_at, published_at). Seeded by importing the 35 runtime tools (installer/runtime-mcp-server/src/tools/register.ts:39-77) + 5 docs tools (installer/revit-api-docs-mcp/src/tools/register.ts:8-15) per E5's mapping.
- **instruction_docs** (id, module_id, kind enum(AGENTS,SKILL), version, content TEXT, published_at, published_by) — repo-root AGENTS.md/SKILL.md served/versioned from the registry per arch §9.
- **promotion_registry** (id, state enum(candidate,promoted,watch,rejected), match_reasons TEXT[], candidate_action, evidence JSONB, updated_at) — direct port of `config/dynamic-tool-promotion-registry.json` (states/entries at lines 4-35) and `-rules.json` (repeatThreshold=2).
- **bridge_releases** (id, version, channel enum(stable,pilot), artifact_storage_key, artifact_sha256, signature, signing_key_id, min_supported_version, released_at, released_by). **release_channels** (channel PK, current_release_id, staged_rollout JSONB). Successor of `releaseRoot\channels\stable.json` + `stable.sig.json` written by CD (.github/workflows/signed-source-free-cd.yml:487); same detached-RS256 signing key is reused (O9 package consumes this table).

**Object storage layout (MinIO bucket `revagent`):** `tenants/<tenant_id>/results/<yyyy>/<mm>/<session_id>/<result_ref_id>.json.zst` (7-day lifecycle rule); `releases/bridge/<version>/{bridge-<version>.zip, manifest.json, manifest.sig}`; `archive/<tenant_id>/{tool_invocations,llm_calls,events}/<yyyy-mm>.ndjson.zst`; `backups/postgres/{base/, wal/}` (O10 warm standby, §7). Instruction docs stay in Postgres (small text), not object storage.

## O7 Event Schema — types, fields, and metric parity (O11)

**Event types and key payload fields** (envelope per P-EVT-1):
1. `session.started` {client_type, entitled_modules[]} / `session.ended` {reason, duration_ms, turn_count, invocation_count}
2. `turn.completed` {engine_mode, router {discipline, data_plane(live|published), complexity}, llm_call_ids[], duration_ms}
3. `llm.call` → typed `llm_calls` row (fields above)
4. `tool.invocation` → typed `tool_invocations` row (fields above, incl. `context` block per P-EVT-5 and `code` block per P-EVT-3)
5. `tool.confirmation` {invocation_id, state requested|approved|denied|expired, user_id, preview_ref} — the D12 `confirm` audit trail
6. `bridge.connected` {device_id, bridge_version, addin_version, revit_version, protocol_version} / `bridge.disconnected` {device_id, reason, connected_ms}
7. `bridge.enrolled` / `bridge.revoked` {device_id, by_user, reason}
8. `bridge.update` {device_id, from_version, to_version, status started|applied|failed|deferred, reason (e.g. deferred_for_revit_close), error}
9. `auth.event` {kind login|login_failed|logout|token_rotated|seat_denied|entitlement_denied|role_changed, subject, detail, ip}
10. `registry.published` {entity tool|module|instruction_doc|bridge_release, entity_id, version, by_user}

**Metric-parity map (E3 checklist → new source).** Surviving metrics:
- machineCount; per-machine name/user/versions → `devices` rows (replaces `reports\machines\*` + status.json identity fields, telemetry.ts:1452-1463).
- connectionState online/stale/offline (server.mjs thresholds 60 s/300 s) → gateway live WSS registry + `devices.last_seen_at`; `bridge.connected/.disconnected` events give history. heartbeatAgeSeconds → `now()-last_seen_at`.
- versionCurrent/upToDate/outdated → `devices.bridge_version` vs `release_channels.current_release_id` (replaces `channels\stable.json` file read, server.mjs:918).
- taskState running/idle; activeTask → open invocations (started, unfinished) per session in the gateway session registry; add-in task-board fields `requestBytes/responseBytes/elapsedMs/error` (revitToolHelpers.ts:464 → telemetry.ts:1312-1341) → `tool_invocations.request_bytes/response_bytes/duration_ms/bridge_ms/error_*`.
- update badges "Update failed"/"Pending restart" (deferredForRevitClose) → `bridge.update.status/reason` (replaces `update-latest.json` reports, RevAgent.Reporting.psm1:354-377).
- All-Status-Activity stream phases started/completed/guarded/failed + durations + KB → `tool.invocation.outcome/duration_ms/request_bytes/response_bytes` (replaces `revagent.live.activity.v1` NDJSON tailing, server.mjs:929-932).
- eventCount, sessionCount, byMachine/byUser totals → COUNTs over `events`/`sessions`/`tool_invocations`.
- productionOperationCount + production byProject/byDiscipline/byLevel/byCategory/byMachineUser + taskNameSamples + searchPolicySamples (summarize-usage-intelligence.ps1:1988-1998) → `tool_invocations.context` block (project.projectId, elements.disciplineHint, location.levelName, elements.categories, search.{query,riskLevel,scannedElementCount,partial,scanStoppedReason,needsScope}) — field-for-field from `revagent.production.context.v1` (telemetry.ts:1102-1179).
- friction {guarded, failed, slow} → outcome enum + duration_ms threshold query.
- sendCode block: count/safeCount/rawCount/manualTransactionCount/writePatterns/classifications (summarize-usage-intelligence.ps1:2004-2021) → `tool_invocations.code` {hash, length, line_count, write_patterns[], has_manual_transaction, preview} for `core.code.execute`/`core.code.preview`.
- toolUsage/commandUsage metrics (count, avg duration, success rate) → aggregates over `tool_invocations` grouped by tool_name.
- promotion/nativeTool/hotfix/reconciliation/annotationInventory candidates + evidenceStrength + humanReviewRequired → **derived analytics**, recomputed by the migrated Usage Intelligence from the raw fields above (code hash repeats vs `promotion_registry.repeatThreshold`, write_patterns, guarded reasons, search.partial/scanStoppedReason). Parity requirement = raw inputs present, not pre-cutover reimplementation of the 2,034-line PowerShell summarizer.
- Token spend / latency distributions / cost attribution (§5.10) → `llm_calls` + `usage_rollups_daily`. **Net-new** — no workstation-era counterpart existed (per-machine API keys had no metering).

**Workstation-era metrics that die (no O7 mapping, by design):**
- NAS write-queue health `writeHealth {inFlight, dropped, maxInFlight}` (telemetryWriters.ts:76-83) — no NAS queue exists; gateway ingestion health is an ops metric, not tenant data.
- File-pipeline accounting: `badEventLineCount`, `eventFileCount`, `machineReportCount` (summary `source` block, summarize-usage-intelligence.ps1:1966-1971).
- NAS updater run-report files `latest.json`/`update-`/`reinstall-`/`install-`/`source-free-migration-latest.json` — die at NAS retirement (D11 step 5); replaced by `bridge.update` events.
- Live-status file cache/merge semantics (`LIVE_STATUS_CACHE_TTL_MS` server.mjs:15-16; `mergeExistingLiveStatusSnapshot` telemetry.ts:1490-1511) — gateway connection registry is authoritative.
- Event fields `connection {targetPresent, hostPresent, port}` (telemetry.ts:1787-1791) — die with the connectionTargetSchema mixin (Gateway session routing).
- LLM-supplied `taskName/taskId/parentTask*` metadata (telemetry.ts:1841-1844) — die with the taskMetadataSchema mixin; replaced by orchestrator-generated `session_id/turn_id/invocation_seq` + a plan-step label.
- Codex session export + 45-minute correlation (addons/usage-intelligence/scripts/export-codex-session-context.ps1, correlate-usage-sessions.ps1) — the Gateway owns the loop (D9), so every event natively carries `session_id`; correlation is intrinsic.
- Summary publisher operational artifacts (`publish-latest.json`, `publish.lock`) and the local telemetry mirror spool `C:\ProgramData\DPE\revAgent\state\telemetry` — replaced by gateway job runs; the bridge keeps only its idempotency journal.

## (d) Test Strategy

- **Migrations:** CI job (extend `.github/workflows/ci.yml` with a `postgres:16` service container — Linux runner, no self-hosted dependency) runs blank-DB `migrate up`, then upgrade-path tests from each tagged schema version.
- **Tenant isolation:** even though Phase 1 is single-tenant, all integration tests seed **two** tenants and assert RLS blocks cross-tenant reads/writes on every tenant-scoped table (cheap now, per §5.9's own logic).
- **Schema round-trips:** zod property tests per event type; golden-file tests pinning `params_summary`/`code` output against fixtures captured from the current runtime's summarizers (ensures parity math sees identical fields pre/post migration).
- **Parity:** P4-T10 harness in CI + run against real pilot traffic during D11 step 2; the pilot week's dashboard numbers are manually cross-checked against the still-running NAS dashboard on the untouched fleet (both systems observe disjoint machines, so compare shapes/derivability, not values).
- **Auth:** Keycloak testcontainer integration tests (login, JWT validation, role mapping); device-token suite covering rotation crash windows (kill bridge mid-rotation, verify grace-window recovery) and revocation latency.
- **Load:** bulk-insert benchmark for `tool_invocations` (target: sustain 50 invocations/s for 10 min on Compose-on-laptop-class hardware with p95 insert < 50 ms — far above the ~12-machine Phase-1 reality, providing SaaS headroom evidence).
- **Restore:** schema/backup interaction validated inside the O10 restore drill (mandatory per §7) — parity harness re-run post-restore proves the archive+backup pair is sufficient.

## (e) Risks (specific to this package)

1. **Partitioning × RLS × upsert interplay.** `INSERT … ON CONFLICT` on a partitioned table requires the unique key to include the partition key; `(tenant_id, idempotency_key)` therefore needs `started_at` in the key or a non-partitioned idempotency side-table. Resolve in T1 spike (side-table recommended); discovering this late corrupts the audit-dedup story.
2. **Keycloak footprint on the spare office PC** (~512 MB+ JVM). Mitigation: single realm, tuned heap; fallback is any embeddable OIDC provider — the gateway's pure-OIDC contract (P-AUTH-1) makes the swap non-breaking.
3. **Privacy of bounded text in a future multi-tenant store.** Today's summaries deliberately keep task names, queries, and code previews (docs/REVAGENT_USAGE_INTELLIGENCE.md:463-470) — acceptable office-internal, sensitive cross-tenant. The envelope carries the bounds config per tenant from day one; SaaS onboarding must revisit defaults (flagged, not solved, here).
4. **Audit-table bloat from chatty tools.** The `audit_exempt` flag (P-EVT-4) covers status polling, but new tools default to audited; registry review must classify each E5 tool at import time or partitions grow faster than the retention model assumes.
5. **Identity mapping at cutover.** Current "identity" is a Windows username env var; enrollment night must bind each machine's device to a real OIDC user (T4 admin CLI includes a `--assign-user` step). Un-mapped devices would produce audit rows with device-only actors, weakening the §6 liability chain.
6. **Parity scope creep.** The candidate/classification analytics (promotion, hotfix, reconciliation) are derived; if stakeholders demand pixel-identical summaries pre-cutover, the 2,034-line summarizer gets re-implemented on the critical path. The plan's position (raw-field parity, analytics recomputed post-cutover by the admin-plane package) must be confirmed once by the coordinator and frozen.
7. **Feature freeze pressure:** registry seed (T1) snapshots the 35+5 tool set; any tool change during migration invalidates the seed and the E5 name map — enforced by the freeze (arch §8), but the seed migration should be regenerable from `register.ts` by script, not hand-written, to absorb late fixes.
