# Package P7 — Admin-Plane Migration (O11): Dashboard, Usage Intelligence, Metric Parity, Archive

## (a) Scope & Non-Goals

**In scope**
- Migrate the two admin-only layers (`addons/dashboard/`, `addons/usage-intelligence/`) from workstation-era NAS-file collection to **read-only consumers of the Gateway data layer** (Postgres + O7 event stream), per Section 5.10's design rule: *no separate collection pipeline*.
- The normative **metric-parity check table** (below): every metric the admin plane shows today, mapped to its O7 event/field or gateway table, with keep/transform/drop status. This table is the O11 pre-cutover gate artifact and the field-requirements handoff to the O7 telemetry-schema task.
- Dashboard evolution per E3's reuse assessment: **adapt, don't rewrite** — keep the proven frontend (`addons/dashboard/public/{index.html,app.js,styles.css}`) and the `revagent.dashboard.snapshot.v1` / `revagent.dashboard.brief.v1` response contracts; swap the data-source layer (all NAS `readJsonFile`/NDJSON-tail code in `addons/dashboard/server/server.mjs`) for gateway queries; retire the workstation add-on packaging, VBS autostart, and the dashboard-specific Cloudflare tunnel.
- Usage-intelligence rebuild as SQL views + one nightly gateway job; retirement of the PowerShell summarizer chain and the Codex transcript exporter.
- RBAC gating of all admin surfaces with the `admin` role delivered by P4 (today the dashboard has **zero** application auth — `server.mjs` contains no auth code; protection is loopback bind `127.0.0.1:8765` (`installer/install-dashboard-addon.ps1:12-14`) plus an out-of-repo Cloudflare Access policy).
- The before-cutover **side-by-side parity verification** during the pilot, and the **cutover-night minimum admin surface**.
- Read-only archive of historical NAS data (decision execution; the "no migration" decision itself is closed in O11).

**Non-goals (explicit)**
- **No cross-tenant analytics** and no vendor-admin/tenant-admin split yet — single-tenant Phase 1; queries are written `tenant_id`-scoped from day one but only one tenant exists. Aggregated/anonymized cross-tenant views are a later product decision (Section 5.10).
- **No historical data migration or backfill** — the new store starts fresh (O11, closed).
- **No new admin features** during the freeze: no alerting/notifications, no new charts, no token-spend dashboards beyond a raw counter once P4/P5 metering data exists. Parity or explicit drop only.
- **No re-architecture of what the metrics mean** — thresholds (stale=60 s, offline=300 s, `server.mjs:13-14`), lifecycle phases, and candidate-mining rules (`config/dynamic-tool-promotion-rules.json`, `config/dynamic-tool-promotion-registry.json`) carry over as data.
- Ops-level observability of the Gateway itself (process metrics, ingestion health) is the Gateway package's concern, not P7 — P7 only consumes it where it replaces a dropped metric (see writeHealth row).

## (b) Plan-Level Design Decisions

- **P-ADMIN-1 — Dashboard migrates by data-layer swap, not rewrite.** Keep `public/` UI and the snapshot/brief JSON contracts (pinned today by `addons/dashboard/tests/smoke-test.mjs`); replace the per-request NAS file reads (`server.mjs:915-944`) with a gateway data-source module. *Rationale: the contract and UI are proven and test-pinned; only the collection layer is workstation-era.*
- **P-ADMIN-2 — Dashboard is served by the Gateway as admin routes** (`/admin/api/overview|brief|fleet` + static `/admin/`), behind gateway OIDC with `role=admin` (P4). The workstation dashboard add-on, its scheduled-task/VBS/HKCU-Run autostart chain (`installer/install-dashboard-addon.ps1:265-359,387-415`) and the dashboard Cloudflare tunnel (`installer/install-dashboard-tunnel.ps1`) are retired at cutover; remote admin access rides the Gateway's single public endpoint (Section 7 tunnel). *Rationale: eliminates an unauthenticated loopback server plus a second exposure path.*
- **P-ADMIN-3 — Parity gaps are closed only by adding O7 fields, never by side files** (implements Section 5.10's design rule). The metric-parity table below is normative; each TRANSFORM/KEEP row that names a new O7 field is a requirement on the O7 schema task. *Rationale: architecture design rule; prevents the NAS pattern from re-growing.*
- **P-ADMIN-4 — Usage intelligence = SQL views for aggregation + one nightly gateway job for rule-driven mining.** Pure GROUP-BY metrics become views; the candidate miner (promotion/native-tool/hotfix/reconciliation/annotation-inventory candidates, evidenceStrength, humanReviewRequired) is ported from PowerShell to a TypeScript job that consumes the **unchanged** rules/registry JSON (`addons/usage-intelligence/scripts/summarize-usage-intelligence.ps1:268-286` loads `config/dynamic-tool-promotion-{rules,registry}.json`). *Rationale: aggregations are trivial SQL; the mining rules are product know-how worth porting as data + one small module.*
- **P-ADMIN-5 — Daily summary contract preserved as `revagent.usage.summary.v2`.** The nightly job materializes a JSON document with the same top-level keys as v1 (`summarize-usage-intelligence.ps1:1961-2022`) minus dropped file-pipeline fields, stored in Postgres (+ object storage copy). *Rationale: keeps old-vs-new diffing mechanical during the pilot and keeps `/api/brief` + LLM-review-pack consumers alive cheaply.*
- **P-ADMIN-6 — Codex transcript exporter and session correlation are retired, not ported.** Gateway-owned sessions (D9) capture user requests, assistant outcomes, and tool calls natively under one session id, making the transcript scrape (`export-codex-session-context.ps1`) and the telemetry↔transcript join (`correlate-usage-sessions.ps1`) structurally unnecessary. Accepted gap: sessions driven by external MCP clients against the north surface (O8 interim) expose tool calls but not free-text prompts. *Rationale: the exporter exists only because the loop is not owned today.*
- **P-ADMIN-7 — Cutover-night minimum admin surface is deliberately tiny:** one `/admin/api/fleet` endpoint + page showing (machine, user, bridge version + up-to-date flag vs release manifest, connection state, heartbeat age, in-flight task) and a **last-error feed** (most recent 50 `failed`/`guarded` invocations with machine, tool, error class, message, timestamp). Nothing else blocks cutover; full dashboard and usage views may land during the 2-week rollback window. *Rationale: the D11 cutover needs exactly "did every machine connect and execute" plus "what broke".*
- **P-ADMIN-8 — Historical data: freeze read-only at cutover, archive at NAS retirement.** At cutover the NAS `reports\` tree goes read-only (ACL, same mechanism family as `scripts/set-nas-release-acl.ps1`); the old dashboard may keep running against it during the 2-week freeze. At NAS retirement the tree is compressed to `archive/nas-reports-final-<date>.tar.zst` + SHA-256 manifest in the Gateway object-storage volume, retained ≥12 months, admin-download only, **no query tooling**. *Rationale: O11 closed "no migration"; the archive is reference/insurance, not a data source.*
- **P-ADMIN-9 — Parity verification is an automated diff, not a review meeting.** During the pilot, old snapshot/brief/summary outputs (captured on the Windows admin workstation) are diffed against the new admin API for the pilot machine/days using the parity table as the checklist; signoff on that diff is the O11 pre-cutover gate. *Rationale: mechanical, reuses the smoke-test fixture approach, auditable.*

## (d) Test Strategy

1. **Contract tests from the existing smoke test.** `addons/dashboard/tests/smoke-test.mjs` (builds a fake reports tree, asserts snapshot/brief shaping) is repurposed twice: its assertions become the schema-contract suite for the new `/admin/api/overview|brief` (seeded Postgres instead of fake files), and its fixture tree becomes input to the parity harness.
2. **Golden parity fixtures.** Because this Linux CI cannot run the PowerShell chain, old-side outputs (`latest.json` summaries, overview/brief captures) are recorded on the Windows admin workstation during the pilot and committed as fixtures; CI replays the equivalent events into Postgres and diffs normalized JSON. Covers rows 13-20 mechanically.
3. **SQL view tests** against disposable Postgres (docker compose in CI) seeded with edge cases the current heuristics handle: started-without-terminal invocations, "guided unsupported" outcomes (must arrive pre-normalized per row 12), nested batch invocations, duplicate redelivery (idempotent journal — no double-counted audit rows).
4. **Candidate-miner golden tests**: port cases from `addons/usage-intelligence/tests/test-usage-intelligence.ps1` into the TS suite; identical rules JSON + event set must yield identical candidate lists and evidenceStrength.
5. **RBAC tests** (with P4): every `/admin/*` route returns 401/403 without `admin`; no route is reachable unauthenticated even from localhost — the loopback-no-auth model must not reappear.
6. **Cutover-night drill**: scripted check that `/admin/api/fleet` lists a just-enrolled bridge within one heartbeat interval and surfaces a forced tool failure in the last-error feed — rehearsed during the pilot, re-run on cutover night per machine.
7. **Archive verification**: restore-and-hash check of the tar.zst on a clean machine before deleting anything from NAS (mirrors Section 7's "untested backup is not a backup" rule).

## (e) Risks (package-specific)

- **R1 — O7 misses admin-only fields** (requestBytes/responseBytes, document context, guardReason) because they look dashboard-cosmetic. Mitigation: P7-T1 is a formal handoff with per-field issues; P7-T8 diff catches any miss before cutover while NAS data still flows.
- **R2 — Remote admin visibility gap at cutover.** Retiring the dashboard Cloudflare tunnel before the Gateway's own public endpoint (Section 7) is proven leaves admins blind remotely. Mitigation: T3 minimum surface is validated through the Gateway tunnel during the pilot; the old dashboard+tunnel stays alive read-only through the 2-week freeze as fallback.
- **R3 — Candidate-miner drift** in the PS→TS port silently changes promotion signals. Mitigation: golden tests (test item 4); all candidates remain human-review evidence by policy (`summarize-usage-intelligence.ps1:2016`), so drift cannot auto-trigger work.
- **R4 — Poll-path load on Postgres**: the UI polls every 3 s (`public/app.js:505`); naive audit-table scans would grow with event volume. Mitigation: fleet state from the small heartbeat table, activity feed from an indexed recent-events query with LIMIT, brief cached ~30 s server-side; acceptable at Phase-1 single-instance scale, revisit for SaaS.
- **R5 — Dual-write confusion**: if admin-workstation scheduled tasks aren't disabled at cutover, NAS keeps receiving summaries/exports and someone reads stale data. Mitigation: T9 checklist driven from the `ownedScheduledTasks` manifests; post-cutover assertion that NAS `reports\` mtimes stop advancing.
- **R6 — Accepted visibility regression** for external-MCP-client sessions (O8 interim): tool calls audited, free-text prompts absent (row 21). Documented and accepted; disappears as usage shifts to the gateway-owned loop/web client.
- **R7 — Scope creep under feature freeze**: the brief/candidate surface invites "one more metric". Mitigation: P-ADMIN-7 fixes the cutover minimum; anything not in the parity table is post-freeze backlog by definition.
